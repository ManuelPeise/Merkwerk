# 008 – IDs as long; Guid ClientId only for attempts and answers

- Status: Accepted
- Date: 2026-10-02
- Ticket: LP-002

## Context

The developer prefers `long` keys. The later offline mode needs IDs that a client can create without the server.

## Decision

All entities use `long Id` (AUTO_INCREMENT). `Attempt` and `Answer` additionally have a unique `Guid ClientId` generated by the client.

## Alternatives considered

- UUID v7 everywhere – larger keys, not the developer's preference.
- Only long IDs – offline sync would need ID mapping later.

## Consequences

- Compact, fast InnoDB indexes.
- Duplicate submissions are detected via `ClientId` (idempotency).
- Because IDs are guessable, authorization checks in services are mandatory (ADR 007).
